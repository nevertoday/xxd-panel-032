> 글자와 이미지의 통합 · 문자 체계에 충실한 레터링 · 원본 특징 삽입 · 시각적 자간 · 넓은 여백

XXD Panel 032는 Codex와 호환 에이전트를 위한 이미지 생성 Skill입니다. 사진에서 가장 식별력 높은 윤곽, 비율, 자세, 개구부, 축, 연결, 기능 또는 음형을 추출해 대상 문자 체계의 글자, 한자, 한글 음절 블록, 합자, 속공간, 획 끝, 가로획, 획 접합부 또는 워드마크 전체 실루엣의 실제 구조로 만듭니다.

주요 문구는 확인된 고유명을 우선하고, 없으면 원본에 근거한 짧은 단어나 구를 대상 언어로 만듭니다. 글자와 이미지는 서로 의존해야 하며, 평범한 활자 옆의 분리 가능한 아이콘이 되어서는 안 됩니다. 공통 획 DNA, 정밀한 속공간, 광학적 커닝, 작은 크기와 단색에서의 가독성, 중간 시각 크기, 최소한의 색, 넓은 여백이 성숙한 아이덴티티를 완성합니다.

## 왜 032이 필요한가요

일반적인 ‘사진으로 만든 로고’는 제목 옆의 아이콘, 기성 글꼴 속 작은 그림, 관광 배지 또는 읽기 어려운 그림 수수께끼로 쉽게 무너집니다.

032는 그 순서를 뒤집습니다.

```text
정체성／비율／자세／기능 고정 → 대상 문자 체계의 짧은 주 문구 결정 → 가장 강한 윤곽, 개구부, 축, 연결 또는 음형 추출 → 실제 글자, 속공간, 획 끝, 가로획, 접합부, 합자 또는 전체 실루엣에 삽입 → 나머지 글자를 같은 획 DNA로 다시 그림 → 커닝, 속공간, 시각 중심 정밀 조정 → 축소 및 단색 검증 → 최소한의 색과 넓은 여백 속 중간 크기 워드마크로 제시
```

무관한 사진으로 바꿔도 글자에 삽입된 특징, 워드마크 실루엣, 속공간, 획 논리, 자간 또는 이름이 거의 달라지지 않는다면 032가 아닙니다.

## 032의 시각적 원칙

- **원본 정체성:** 최소 세 가지 구체적 단서로 비율, 윤곽 흐름, 자세, 방향, 동작, 기능과 관계를 보존합니다.
- **원어에 충실하고 근거 있는 이름:** 확인된 고유명 또는 대상 언어의 원본 기반 짧은 말을 사용하며, 소유자나 가짜 문자를 만들지 않습니다.
- **하나의 원본 개입:** 결정적인 윤곽, 기능, 개구부, 연결 또는 음형 하나를 실제 글자 구조에 삽입합니다.
- **양방향 의존:** 개입을 빼면 워드마크가 평범해지고, 글자를 빼도 독립 아이콘이 남지 않습니다.
- **통일된 글자 DNA:** 획 굵기, 끝 모양, 곡선, 각도, 속공간, 기준선과 광학 보정이 하나의 설계 체계에 속합니다.
- **정교한 시각 간격:** 글자쌍 커닝, 내부 속공간, 외부 음형, 오버슈트, 균형과 시각 중심을 의도적으로 조정합니다.
- **축소와 단색 검증:** 워드마크는 썸네일에서도 읽히고 단색에서도 고유합니다.
- **절제된 제시:** 옅은 단색 바탕, 흑백 또는 원본에서 얻은 한 가지 포인트색, 중간 크기의 마크와 넓은 여백을 사용하며 목업과 광고 장면을 배제합니다.

## 예시 · 곧 추가됩니다

저장소에는 향후 예시를 위한 [`assets/examples/`](assets/examples/) 폴더가 마련되어 있습니다. 프로젝트 작성자가 확인한 032 완성작만 추가하며, 그전에는 다른 스타일의 게시물이나 이미지를 자리표시자로 쓰지 않습니다.

향후 예시는 032의 적용 범위만 보여 줍니다. 예시의 주제, 여백 비율, 팔레트, 문구, 화면 비율은 생성 참조나 기본값이 되지 않습니다.

## 네 가지 출력, 하나의 통합형 워드마크 시스템

네 가지 모드는 하나만 또는 여러 개를 함께 선택할 수 있습니다. `1`, `1+3`, `1、2、4`, `전체`라고 답하면 Skill이 중복을 제거하고 1→4 순서로 실행합니다. 각 모드는 별도 작업 폴더에 독립적으로 출력되며 한 장의 모음 이미지로 합치지 않습니다. `전체`는 원본 한 장당 PNG 7개(일반 모드 각 1개＋배경화면 4개)를 만듭니다. 크기는 모드별로 표시해 같은 답변에서 지정할 수 있고, 지정하지 않은 일반 모드는 원본에 맞춥니다. 문구는 기본적으로 선택한 모드가 공유하며 모드별 지정도 가능합니다.

| 모드 | 크기 규칙 | 결과물 |
| --- | --- | --- |
| `top-bottom` | 원본 적응형 | 위에는 전체 원본, 아래에는 032 원본 특징 통합형 맞춤 워드마크. 두 패널이 원본 크기를 유지하며 정확히 50/50 |
| `left-right` | 원본 적응형 | 왼쪽에는 전체 원본, 오른쪽에는 032 원본 특징 통합형 맞춤 워드마크. 두 패널이 원본 크기를 유지하며 정확히 50/50 |
| `design-only` | 원본 적응형 | 원본 사진은 보이지 않고 변환 디자인만 표시. 원본 비율과 크기 유지 |
| `wallpaper-pack` | 기기별 네 가지 크기 | 휴대전화, iPad, 데스크톱, 어린이용 스마트워치 PNG 개별 출력 |

정확한 사용자 픽셀 > 지정 비율 또는 용도 > 일반 모드의 원본 적응형 순서입니다. 원본 `032.md`의 3:4는 초기 창작 캔버스일 뿐 현재 Skill의 숨은 기본값이 아닙니다.

짝을 이루는 모드의 사진은 절제된 색 보정과 필요한 환경 확장만 적용해 사실성을 지킵니다. 디자인 단독과 배경화면은 사진을 근거로 사용하지만 원본을 보여 주지 않습니다.

### 배경화면 세트: 연결형 또는 독립형

배경화면에는 숨은 기본 크기가 없습니다. 일반 프리셋은 휴대전화 `1440×3200`, iPad `2048×2732`, 데스크톱 `3840×2160`, 스마트워치 `1024×1024`이며 기기별 사용자 지정 크기도 가능합니다.

- **연결형 세트(권장):** 먼저 iPad 기준 작품을 생성하고 승인합니다. 나머지 세 기기는 원본 사진＋동일한 기준 작품을 참조해 각 화면에 맞게 새로 구성합니다.
- **독립형 네 작품:** 각 기기는 원본 사진만 참조하며 잠근 주 문구를 유지한 채 워드마크 크기, 원본 특징의 개입 위치, 전체 실루엣, 자간 리듬, 단색／포인트색 관계와 여백 균형을 각각 탐색합니다.

연결형은 크롭이 아닙니다. 네 장 모두 따로 생성하고 구성하며 검수하고, iPad→휴대전화→데스크톱→스마트워치 순으로 참조를 이어 붙이지 않습니다.

## 글자 자체가 디자인 대상입니다

생성 전에 자동 문구, 사용자 지정 문구, 무문자 출력 중 하나를 선택합니다. 문구가 있으면 대상 언어나 지역도 지정합니다.

자동 문구는 확인된 고유명을 우선합니다. 고유명이 없으면 원본의 정체성, 주제, 장소 단서, 동작 상태 또는 뒷받침되는 의미에서 짧고 기억하기 쉬운 단어나 구를 만듭니다. 조직이나 소유 관계를 지어내지 않습니다.

기본은 하나의 맞춤 워드마크입니다. 실제 정보 가치가 있을 때만 훨씬 작은 설명 요소를 0–2개 더합니다. 중국어, 일본어, 한국어, 아랍어, 라틴 문자 각각의 실제 글자 구조를 존중하고, 사용자가 확정한 문구는 글자 그대로 보존하며, 가짜 문자를 만들지 않습니다. 결과는 양방향 의존 테스트와 무관한 이미지 교체 테스트를 모두 통과해야 합니다.

사용자가 완성 문구를 주면 그대로 유지합니다. 방향이나 수정 가능한 초안일 때만 대상 독자, 목적, 필수 단어, 어조, 함의를 보존하며 다듬습니다.

언어는 명령문의 언어가 아니라 의도한 독자를 따릅니다.

```text
목표 시장 또는 독자 > 지정한 결과물 언어 > 방향 지시 언어; 모두 불분명하면 생성 전에 질문
```

일본판은 자연스러운 현대 일본어를, 한국 독자용은 자연스러운 현대 한국어와 정확한 띄어쓰기를, 영국판은 영국 영어를 사용합니다. 아랍어판은 기본적으로 자연스러운 현대 표준 아랍어와 올바른 오른쪽에서 왼쪽으로 흐르는 구성을 사용합니다. 외모, 옷, 풍경, 간판으로 국적을 추측하지 않으며 가짜 외국어 문자를 쓰지 않습니다.

## 정확한 합성은 코드가, 작품은 이미지 생성이 맡습니다

이미지 모델이 원본 특징을 글자 구조에 통합하고, 대상 언어의 맞춤 워드마크, 통일된 획과 속공간, 광학적 커닝, 단색／포인트색 관계, 정제된 실루엣과 넓은 여백을 만듭니다. `scripts/compose_panel.py`는 캔버스 계획, 정확한 50/50 래스터 합성, 최종 크기와 검수만 수행하며 프로그램 그림으로 결과물을 위조하지 않습니다.

```bash
python3 scripts/compose_panel.py --plan --layout top-bottom --source photo.png
python3 scripts/compose_panel.py --plan --layout left-right --size 2560x1440
python3 scripts/compose_panel.py --audit result.png --layout design-only --size 2048x2048
```

정확한 상하 캔버스는 전체 높이, 좌우 캔버스는 전체 너비가 짝수여야 합니다. 요청 픽셀을 몰래 변경하지 않습니다.

## 경계와 신뢰

- 각 사진은 독립된 작업 안에서만 사용하며 다른 입력, 과거 결과, 예시의 피사체, 색, 문구, 구도를 빌리지 않습니다.
- 호출할 때마다 새 작업 폴더를 만들고 원본과 조건이 같아도 새로 생성합니다.
- 결과물은 PNG 비트맵이며 SVG, HTML, Canvas, 프로그램 드로잉 대체물이 아닙니다.
- 설정된 비트맵 브리지는 정제된 상태만 출력하며 공급자, 엔드포인트, 헤더, 인증 정보, 프롬프트, 응답 본문을 노출하지 않습니다.
- 선택한 일반 모드마다 파일 1개를 반환하고, `wallpaper-pack`을 선택하면 독립 배경화면 4개를 추가합니다. `전체`는 원본 한 장당 PNG 7개를 네 개의 동급 모드 폴더에 저장하며 모음 이미지로 합치지 않습니다.

로컬 합성에는 Python 3와 Pillow가 필요합니다. 안전한 비트맵 브리지는 Python 3.11 이상의 `tomllib`을 사용합니다. 이미지 생성에는 내장 래스터 기능이 있는 호스트 에이전트 또는 이미 설정된 호환 경로가 필요합니다.
